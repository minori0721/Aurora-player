# 技术说明

[项目首页](../README.md) · [使用指南](usage.md) · [源码结构](architecture.md)

本文集中记录影响行为的实现机制、参数与边界。日常操作见使用指南；参数调整时优先更新本文，避免在多个功能列表重复维护数值。

## 双播放引擎

本地文件和在线完整加载使用 Web Audio 的 `AudioBuffer`；在线流式使用原生音频元素，经 `MediaElementAudioSourceNode` 接入现有音量与分析节点。这里的流式是音频文件渐进播放，不是自行实现 HLS、MSE 分片或独立解码器。

未保存偏好或偏好不可读时默认流式优先，已明确选择完整加载时保留原设置。设置只影响后续在线播放。单曲循环已启用时，在线选歌直接走完整加载；流式播放中再请求精确功能时按需准备完整 PCM。

### 生命周期与完整准备

- 暂停保留当前原生播放实例，继续播放不主动重建或重下。
- 选择下一首时释放上一首实例、音频节点和自有 Blob URL，并取消旧加载。浏览器 HTTP 缓存和进程内存不保证同时立即释放。
- 浏览器自行决定原生缓冲的下载、保留和回收，缓冲到末尾不等于永久离线缓存；拖动到已回收区域时可能再次请求。
- 完整预取的字节可通过 Blob 交给原生引擎，不额外解码；在途完整预取继续接管，不为切换偏好中止后重下。
- 原生缓冲不开放给页面读取完整压缩文件。精确循环、试听、智能分析或失败兜底可能再次请求整首，不能保证浏览器缓存一定复用网络传输。
- 同一曲目的完整准备任务共享，完成后保留当前 PCM，重复分析或循环复用；智能分析没找到候选时也不会立即丢弃这份 PCM。
- 真正切换引擎时读取最新进度与播放意图，准备期间的暂停、跳转和切歌不能被旧任务覆盖。

开启 A/B 的准备完成前不启用循环。用户改动循环输入、取消设定或切换播放模式后，过期回调不能重新应用旧区间。分析试听的定时停止也检查曲目、音源和操作版本，不能停止后来播放的歌曲。

### 音质标签与内存

普通流式标签首先使用 API 的格式、采样率、码率。FLAC 位深优先从已有完整预取 Blob 的前 4 KiB 读取；否则只尝试一次 `Range: bytes=0-4095`，最多等待 3 秒。

仅接受可用的部分响应；服务器忽略 Range、范围不符、正文超限、缺少可限制读取的流接口或探测失败时放弃。`Content-Range` 因跨域未开放时可依据部分响应和读取上限处理，不能因此转为整文件读取。探测不带账号凭据，不启动音频解码，迟到结果检查当前曲目、账号和完整解码状态。

位深只来自有效 FLAC STREAMINFO，不从 API 猜测，也不把 Web Audio 的浮点采样格式当作源位深。MP3/AAC 不标成与无损 PCM 同义的 `16bit/24bit`。完整解码后优先用文件头描述源格式，不把音频上下文的输出采样率冒充源采样率。

由流式准备完整音频的路径使用以下防护：

| 数据 | 桌面通常上限 | 窄屏或低内存设备通常上限 |
| --- | --- | --- |
| 完整压缩文件 | 128 MiB | 64 MiB |
| 预计整首 PCM | 256 MiB | 128 MiB |

PCM 按时长、声道和不低于 48kHz 的采样率估算，超限时拒绝该次完整准备，不强行解码。这些不是整个页面内存预算：浏览器缓冲、解码临时数据、分析 Worker、图片和图形资源还会额外占用内存。原有本地与完整加载也不是不受设备内存限制。

## 超时与失败恢复

| 阶段 | 当前限制 | 处理 |
| --- | --- | --- |
| 音频 URL 解析 | 最多 30 秒 | 失败时提示，不能用不存在的 URL 下载 |
| 流式启动，尚未取得元数据 | 连续约 10 秒无进展 | 尝试一次完整加载 |
| 取得元数据后的流式播放 | 连续约 15 秒无进展 | 尝试完整加载并保留位置 |
| 完整下载，取得可用响应前 | 最多 15 秒 | 按停滞恢复预算处理 |
| 完整下载正文 | 连续 20 秒无非空数据 | 按停滞恢复预算处理 |
| 可选 FLAC 文件头 | 最多 3 秒 | 放弃补标签，不影响播放 |

流式每秒检查一次，实际触发可能略晚；播放位置前进或当前缓冲增长会重置无进展计时。暂停、离线、页面隐藏或音频上下文未运行时不按正常卡死计时。明确的媒体错误可立即处理，不必额外等满阈值；自动播放被阻止时提示用户，不以完整下载绕过限制。

完整下载的响应等待从传输任务开始计时，包含网络连接、重定向和候选地址切换，不是纯服务端处理时间。已收到 403/404 等错误响应不等于服务器没有响应；跨域失败也可能是浏览器未向脚本开放响应。

流式每个会话最多自动进入一次完整加载兜底。完整传输中，停滞恢复和遇到 `401/403/404/410` 后重新解析 URL 各最多一次，额度由预取和正式播放共享；普通网络错误不无条件清缓存。完整下载持续收到数据时没有总下载时长限制，回退后还需等整首下载与解码完成，并非到阈值就能立即出声。

## 下一首与详情前瞻

预取分别处理音频、歌词和歌曲详情，不把“后续 5 首详情”当成“5 首整音频”。

| 任务 | 触发与范围 |
| --- | --- |
| 本地下一首整文件预读 | 剩余约 10 秒，最多一首，不预解码 |
| 在线完整音频预取 | 通常剩余约 15 秒；不小于 16 MiB 或大小未知时约 25 秒 |
| 流式下一首 | 预取 URL 和歌词；最后约 5 秒且条件允许时预热一个原生播放元素 |
| 歌词 | 随下一首音频预取任务获取原始数据，不在 URL 提前预热时单独扩大范围 |
| 歌曲详情 | 顺序播放最多查看后续 5 个位置，连续已就绪位置不超过 2 个时补齐 |

本地和在线整文件预取通常使用桌面 64 MiB、窄屏/低内存设备或慢速网络 32 MiB 预算。已知超限时直接跳过正文，下载中发现超限时停止；这些是下一首预取限制，不是可播放文件大小或页面总内存限制。

原生下一首预热要求当前缓冲充足且正在播放；后台、省流、2G、低内存、单曲或 A/B 循环不启动这项预热。切歌接管相同原生元素，不因接管而故意重建请求。

歌词预取包含接口提供的原文、翻译、罗马音和逐字数据，缓存可复用 1 小时；后台不解析、不渲染。正式播放接管共享请求，失败时正常获取，不阻塞音频。

详情按歌曲 ID 共享前台与后台请求，已有详情不重复获取；随机模式只补全已锁定的下一首，单曲与自定义循环不做后续详情前瞻。所有订阅取消后立即移除旧任务，重新进入时不复用已中止任务。

## 本地导入与 SLI

导入流程为完整扫描、路径规范化、配对、解析、替换列表、播放时应用。优先标准文件系统接口，回退旧目录接口时反复读取目录批次直到为空，最后才使用普通文件列表；收集完成前不逐次替换列表。导入串行，按规范路径、大小和修改时间去重。

路径统一分隔符、Unicode NFC 与匹配大小写，保留显示名称。SLI 和 LRC 共用配对基础设施，优先级为：

1. 同目录、完整音频文件名，例如 `foo.wav` 对应 `foo.wav.sli`。
2. 同目录、基础名相同，例如 `foo.wav` 对应 `foo.sli`。
3. 跨目录仅在音频和配套文件基础名都全局唯一时回退。

同一级多候选标记为歧义，不猜测。同路径配套文件再次导入时替换旧文件。包含音频的新批次清理旧配套注册表；只有配套文件时合并并扫描当前整个列表。空列表暂存项只供下一批音频使用一次。

解析 SLI 不直接改变播放或 UI，只保存首个 From/To 的整数采样点，校验 `To >= 0`、`From > To` 和安全整数范围；不执行复杂 SLI 脚本。播放时清除上一首的自定义循环，再按 Base Rate 换算并结合真实时长校验：

```text
Start A = To / Base Rate
End B   = From / Base Rate
```

Base Rate 默认 44100 Hz，只用于 SLI 导入和导出的秒/采样点换算，不改变音频解码采样率或播放速度。导出将秒乘回 Base Rate 并取整。循环终点允许一个来源采样点的边界误差，明显越界则拒绝，不大幅裁剪。无有效 SLI 的下一首不继承旧循环。

目录中的独立 PNG 等图片不自动作为封面。

## 循环与匹配算法

完整播放的单曲循环由音频线程按 `0 → duration` 循环；A/B 和 SLI 优先，按 `B → A` 回跳，不在每圈重新打开文件，也不额外插入交叉淡化。音源本身的静音、编码填充和波形不连续仍可能听出接缝。

智能分析在用户给定粗略 A/B 附近找接点，不扫描整首识别音乐结构：

| 模式 | 方法 |
| --- | --- |
| 速度优先 | 短窗 MSE 模板匹配，主要在 A 附近搜索，并尝试小幅调整 B |
| 均衡推荐 | 约 6kHz 单声道 NCC 粗筛，再回原采样率评分与逐采样点精修 |
| 准确优先 | 更广的起止候选组合与精修，耗时通常更多，但不保证结果更好 |

评分综合局部波形相似度、接缝跳变与斜率、粗点偏移、循环长度变化和风险项。部分符合低风险条件的临界候选会小幅上调评分；评分不是经统计校准的成功概率。

| 评分 | 当前行为 |
| --- | --- |
| 不低于 80% | 自动应用，提示「找到了」 |
| 30% 到 80% 之间 | 也会应用候选，但提示试听确认 |
| 低于 30% | 不自动应用 |

优先在 Worker 中分析，创建或传输失败时回退主线程，回退期间可能短暂卡顿。播放声道不转移给 Worker，而是生成独立可转移的单声道数据；最后一个任务完成后空闲 60 秒释放 Worker，主线程回退完成后释放临时缓存。释放分析数据不等于同时释放当前曲目的播放 PCM。

## 歌词时间与排版

本地来源优先级为配套 LRC、内嵌歌词、启用后的在线搜索。本地匹配先使用 `/search/match` 的标题、专辑、歌手与秒级时长，没有候选或失败时回退 `/cloudsearch`；不额外计算整文件 MD5。候选按文本与时长等信息筛选，不保证任意文件都能正确匹配。

解析支持 LRC、元信息 JSON 和两字段/三字段 YRC。完整 YRC 经行序、文本和时间校验后可作主时间轴；部分逐字数据只替换能确认对应的行，保留其他普通歌词，避免重复。翻译和罗马音优先使用能对齐的 `ytlrc/yromalrc`，缺失或版本不同则回退普通附属歌词，不独立生成主歌词行。

歌词使用时间索引，顺序播放沿游标更新，跳转和循环回跳重新定位。逐字动画跟随音频时钟，只维护当前可见行，暂停、页面隐藏、音频挂起或移出视口后停止，恢复后按当前时间继续。

原文按高亮最大字号预留宽度，用内部缩放区分当前行，只有当前原文加粗，翻译和注音保持较轻字重。长词与逐字片段可折行，不改原时间数据。

滚动、缩放和附属行间距由同一个短时动画帧控制器协调，正常滚动约 400ms，跟随目标提前约 15ms 切到下一行，但实际高亮仍按音频时间。快速换句保留同方向速度衔接，结束后停止更新。手动浏览、暂停和减少动态效果时不预启动跟随滚动。

## 背景、封面与渲染

当前空间背景从封面采样 `64×64` 的颜色分布，使用三轮可分离加权模糊，半径为 **3.5**，最外层样本按小数半径加权。Oklab 调整亮度与彩度，降低黑白区域的支配程度；纯灰度保留中性，全黑与全白分别映射到约 175 和 230 的灰度。

空间色场由低分辨率 WebGL 网格缓慢变形，保留颜色大致方位，按窗口比例铺满而不裁掉边缘颜色。桌面实时画布长边不超过 512px、目标 30fps；窄屏不超过 384px、目标 24fps，不降低界面和封面的清晰度。

颜色约 1 秒过渡，连续切歌从当前混合结果继续；窗口缩放保留流动计时，同地址或采样完全相同的封面复用结果。主题缓存最多 16 项，保留小尺寸采样，不保留整张原图。每帧只更新变形和混合参数，不持续重新上传封面纹理。

封面待定时暂留现有背景，确认缺失、失败或单次读取超过 15 秒后回默认色，仍属于当前曲目的迟到结果可以接上。Worker、OffscreenCanvas、WebGL 不可用或上下文丢失时降为 ColorThief 配色静态渐变，外观不完全相同。暂停后停止流动；页面隐藏或启用减少动态效果时不持续绘制。

主封面由主图、迷你播放器与 Media Session 共用地址。网易云图片按显示尺寸与 DPR 选择 512/768/1024/1536/2048px 缩略图，窗口变化后延迟更新，GIF/APNG/WebP 扩展名保留原地址；超过最大档位可能损失细节。本地封面保留原始 Blob，不额外重编码，主题取色使用最长边 96px 的缩略图，空间背景再生成前述色场。

列表封面共享任务和缓存，优先处理可见区域及前后约 300px；并发上限 4，单次 8 秒超时，失败最多重试 2 次，连续失败冷却 30 秒。动态节点立即注册共享观察器，关闭列表或替换歌单后旧结果不能回填。主封面和迷你封面在解除引用后释放旧 Blob URL，迟到回调检查归属。

普通播放低频更新时间，逐字与换句使用各自必要调度，特效开启时持续绘制。暂停且关闭特效、过渡完成后不持续 RAF；无特效只在需要时清空画布。特效停用、隐藏或减少动态效果时画布退出合成并缩为 `1×1`，恢复前重建。浏览器与驱动可能保留图形缓存，不能保证显存即时下降。

## API、账号与缓存

### 内容与歌单

- 歌单使用 `/playlist/detail` 的完整 `trackIds` 决定顺序，再分批调用 `/song/detail`，首批可先播放。取消保留已加载部分，权限、缺失项和批次失败仍可能造成不完整列表。
- 我的歌单使用 `/user/playlist` 的 `more/limit/offset` 分页，并按 ID 去重。
- 歌手概览优先 `/artists` 一次取信息与热门歌曲，缺字段时回退 `/artist/detail`、`/artist/top/song`；概览预取专辑和 MV 前 30 项、展示前 6 项，标签首页复用缓存。
- 同一实体切标签共享在途请求，单项失败只重试该项；切实体取消旧导航，迟到结果不能覆盖新页。
- `/song/music/detail` 仅在打开下载窗口时按需读取。展示的音质参数不等于账号必然可下载，实际仍受下载接口和 match 结果约束。
- 当前覆盖歌曲、专辑、歌手和官方 MV 外链，不含播客/声音页面或内部视频播放器。

### 缓存与凭据

公共搜索、专辑、歌手等数据可进入 IndexedDB `metadata`；URL 含 `cookie/token/key` 时只用账号内存缓存，登录状态、二维码、账号修改和强制刷新不使用公共缓存。公共键移除 `timestamp/noCache` 等瞬态参数，启动迁移和退出登录清理旧敏感键。

已解析音频链接内存最多 200 项，插入时清理过期项，访问命中优先保留；淘汰后重新解析，不能把链接缓存当作音频正文缓存。

扫码串行轮询，短信通过 `/captcha/sent/v1` 发送、`/login/cellphone` 登录。手机号、验证码和校验凭据放 POST 正文，不写缓存或 Debug 日志；登录凭据仍保存在当前站点 localStorage，用于恢复账号，不是浏览器之外的秘密存储。

短信默认间隔 60 秒，服务器可读的更长 `Retry-After` 优先；倒计时在当前页面内存保存，不跨刷新。账号校验和会员查询独立，15 秒超时覆盖正文，会员失败不阻塞已确认的登录。关闭登录、切方式、刷新二维码或退出会取消旧任务；临时账号校验失败只重试校验，不自动重新发短信。

账号提交前检查代数与凭据快照，旧响应不能恢复已退出账号或覆盖后来的音质选择。下载窗口音质探测最多两项并发，关闭后不继续请求兜底链接，已启动的下载不撤回。

### 恢复与异步边界

播放列表以结构化字段保存在 IndexedDB `player-state`，本地存储保留无句柄的轻量备用快照；旧 schema 2 和旧快照迁移不从歌名显示字符串拆分。列表和选中位置用同一事务读写，只有内容变化才保存完整快照，选中位置携带列表身份与内容版本。

恢复时按路径、大小和修改时间仅补回唯一匹配的文件句柄，不能从其他列表借用索引。保存元数据不等于保存本地音频或伴随文件正文；被禁用、写满或强制终止时最后一次保存仍可能失败。

本地读取、解码、歌词、封面、歌单和在线请求分别校验当前播放令牌、曲目身份、导航令牌或账号代数。取消共享请求只解除当前订阅，其他使用者仍可继续；没有订阅者的任务及时移除，避免下次复用已中止请求。

播放列表、循环、分析、音量和高级面板在退出动画结束后设为 `hidden`；快速重开撤销旧隐藏任务，与模态窗口共用背景锁定。Debug 仅保留最近 1000 条日志，隐藏时不自动滚动。
